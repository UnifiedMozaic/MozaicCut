# 音の処理（src/effects/dsp/）

M3（音）の部品です。音の効果（EQ、ダイナミクス、パン、フェード）と解析（ラウドネス、話し声の区間、波形）を、UnifiedMozaic で書いています。
使う人向けの説明は README.md、全体の約束ごとは [architecture.md](architecture.md) にあります。

## 約束ごと

- **音の形**: f32 のステレオ（`L, R, L, R, ...` の `f32[]`）。標本化周波数は 48 kHz が基本です（どれも `rate` を受け取るので 44.1 kHz なども使えます）。`src/engine/audio.um` の `mix` と同じ並びです。
- **処理の形**: `dspXxxProcess(mut 状態, mut buf, frame0, frames)`。buf の `frame0` フレーム目から `frames` フレームを、その場で書き換えます。状態（フィルタの記憶など）は struct に持ちます。
- **分け方によらない**: どの処理も 1 標本ずつの決まった順の計算です。何フレームずつに分けて渡しても、結果はビットまで同じです（`tests/dsp` の `chunk_*` で確かめています）。フェードや音量の曲線は、位置を「素材の先頭からのフレーム番号」（`pos0`）で受け取ります。
- **途中から（シーク）**: 「分けても同じ」は、素材の先頭から続けて処理した場合の話です。状態を持つ処理（EQ や K 特性の IIR、コンプやゲートの包絡、リミッターの先読みとリリース）を区間の途中から冷えた状態で始めると、全体を書き出したときと違う音になります。範囲の書き出しやプレビューの途中からの再生では、(a) クリップを素材の先頭から処理して使いたい位置から使う（ビットまで同じ）か、(b) `dspPrerollFrames(rate, いちばん長い時定数 ms, リミッターの遅れ)` フレームの助走をしてから使う（最低 1 秒、時定数の 10 倍。差は 1e-4 以下）か、のどちらかにします。マスターのリミッターも同じように助走します（`preroll_*` で確かめています）。
- **NaN と無限大**: バイクアッドは、かたまりの終わりに状態が有限でなければ 0 に戻します（そのかたまりの出力だけが NaN を含み、次から戻ります。戻した回数は `dspEqToJson` の `resets` と `dspEqDescribe` で知らせます）。コンプとゲートの検出、ラウドネスの測定、話し声の検出は、有限でない値を飛ばすか無音として扱います。
- **決まった結果**: 指数・対数・三角関数は `math.um` の多項式で計算します（C の libm に頼らないので、どの OS でも同じ値になります）。内部の計算は f64 です。
- **CPU と GPU で同じ結果**: 波形の縮約の最下段は kernel（`dspWaveBlockKernel`）です。`cpu.dispatch` と `gpu.dispatch`（wgpu）の結果がビットまで同じことを `tests/dsp/wave_gpu.um` で確かめています。
- **人にも AI にもわかる**: 設定と結果は `...ToJson`（機械向けの JSON）と `...Describe`（日本語の文）で出せます。
- **名前**: 全ファイルで名前の空間が 1 つなので、すべて `dsp` / `Dsp` / `DSP_` で始めます（ファイルの中だけの補助は `dspm`・`dspl` などの前置き）。

## 確かめたこと（`node tests/dsp/run.mjs`）

- 数学の関数が JavaScript の `Math` と相対誤差 2e-15 以内で合う。
- バイクアッドの係数が RBJ の式（JavaScript で計算）と合う。応答の式と、正弦波を通して測った値が 0.05 dB 以内で合う。
- ラウドネス: EBU Tech 3341 の 1〜5 番（1 kHz の正弦波 -23 / -33 dBFS、ゲートの試験）が ±0.1 LU、Tech 3342 の 1〜4 番（LRA 10 / 5 / 20 / 15 LU）が ±1 LU で合う。44.1 kHz とモノラル、s16 のファイルからも測れる。
- 真のピーク: 係数が BS.1770-4 の表と同じ。EBU Tech 3341 の真のピークの番（15〜19 番）に倣った信号（fs/4・fs/6・fs/8 で山が標本の真ん中、-6 dBTP と +3 dBTP）と、山がちょうど半標本の位置に来る 1〜20 kHz の正弦波が、規格の許容 +0.2 / -0.4 dB に入る。JavaScript で独立に実装した参照と 1e-4 dB で合う。
- リミッター: +7 dBTP の入力が、天井 -1 dBTP 以下になる。さらに、19 kHz / 20 kHz の正弦波、白色雑音、11 kHz + 雑音、低域通過の雑音、音楽のような信号で、出力を run.mjs の独立の参照（BS.1770-4 の係数）で測って -1 dBTP 以下（+0.005 dB まで）、最後の標本クリップに当たる標本が 0.1 % 以下。静かな音は遅れだけで、そのまま通る。
- 話し声: 無音のあとの白色雑音・雑音だけ・無音のあとの低域通過の雑音で区間が 0 個。雑音の上の話し声と、頭からの話し声は見つかる。ダッキングは、アタック 0・リリース 0 でも階段になる。
- 波形: 少しずつ足したもの（ばらばらの長さ、kernel のかたまりごと、ファイルから）が、全体を一度に渡したものとビットまで同じ。
- NaN と無限大: EQ・コンプ・ゲートが元に戻り、ラウドネスは無音として測る。EQ の設定の誤り（知らない種類など）を受け付けない。
- 途中からの処理: 助走をすれば全体の書き出しと 1e-4 以下で合い、素材の先頭からならビットまで同じ。
- コンプレッサーの静的な特性（ニーの曲線）、アタックの時定数、ゲートの開閉、パンの電力の和、フェードの曲線、クロスフェード。
- 話し声の区間（始まりが ±50 ms）、低音（60 Hz）は話し声と見なさない、ダッキングのキーフレームと BGM の音量。
- 波形の縮約で、普通の関数と kernel、CPU と GPU の結果がビットまで同じ。

`node tests/dsp/run.mjs --bench` で、1 分の 48 kHz ステレオを処理する時間を出します。

## 真のピークの精度の限界

真のピークは規格どおり 4 倍の標本化なので、山が補間の点の間（最も離れて 1/8 標本）に来ると低く読みます。止まっている正弦波で、高域（18〜20 kHz）では最大でおよそ 0.5 dB 低く読むことがあります（規格もこの誤差を認めていて、EBU Tech 3341 の許容は +0.2 / -0.4 dB です）。白色雑音のように 20 kHz を超える成分が多い音では、もっと細かく（16 倍の sinc で）補間すると、リミッターの出力の山が天井より 0.5 dB ほど高く出ることがあります。BS.1770 の dBTP としては天井以下ですが、のちの変換（MP3 や AAC への符号化、標本化周波数の変換）で山が上がることも考えて、**天井には余裕を持たせ、-1 dBTP 以下（配信用なら -1〜-2 dBTP）を勧めます**。
