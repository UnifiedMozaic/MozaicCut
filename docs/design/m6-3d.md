# M6: 3D レイヤーとカメラ（`src/effects/threed/`）

After Effects の 3D レイヤーに当たる部品です。平面のレイヤー（映像・画像・文字・色）を 3D の空間に置き、カメラから遠近の投影で描きます。
ライト（任意）、モーションブラー、被写界深度、アンチエイリアスも同じ kernel で扱います。

## できること

- **レイヤーの 3D の変形**: 位置（2D で置いた所からのずれ `ox` / `oy` と奥行き `z`）、回転 `rx` / `ry` / `rotation`（度）、拡大 `scale`（数か 横,縦）、基準点 `anchor`（x,y。レイヤーの中央からの画素）。掛ける順は AE と同じ（位置 · Rx · Ry · Rz · 拡大 · (−基準点)）。
  - 回転の向き: `rx` が正なら下の辺が奥へ・上の辺が手前へ倒れる。`ry` が正なら右の辺が手前へ・左の辺が奥へ回る。`rotation` が正なら画面の上で時計回り。座標は x が右・y が下・z が奥（右手系。AE と同じ決まり）。試験で、`rx=40` の上の辺が下の辺より広く、`ry=40` の右の辺が左の辺より高いことを確かめている（AE の `toComp()` の数値とは突き合わせていない）。
- **カメラ**: 位置と注視点、横の画角（`camera.fov`）かズーム（`camera.zoom`、画素）、視線のまわりの回転（`camera.roll`）。既定は AE の 50mm 相当で、`z=0` の拡大 1 のレイヤーは 2D で置いたのと同じ大きさに見える。**標本が 1 つ（`camera.aa` を書かない）か、モーションブラー・被写界深度の標本だけのとき**は、止まった `z=0` のレイヤーは 2D と同じ画素に描かれる（`camera.aa` を書いたときだけ、画素の中の位置をずらしてアンチエイリアスする）。
- **奥行きの順の重ね**: 画素ごとに、そこに写るレイヤーを奥行きで並べて奥から重ねる。交わるレイヤーも画素ごとに前後が入れ替わる。奥行きの差が 0.001% 未満なら同じ面とみなし、行の順（後の行が手前）。距離 50000 の望遠でも 0.5 画素の差で前後が決まる（試験で 20 画素の前後を確かめている）。カメラより後ろ（1 画素より近い所）は描かない。
- **射影変換と補間**: 画面の画素から射影の逆行列でレイヤーの座標を引き、双一次で補間する。色は端の texel にくっつけて読み（clamp-to-edge）、縁の透明さは「面の四角にどれだけ入っているか」（画面の 1 画素の幅）で付ける。大きく拡大しても縁はぼやけず、画面の 1 画素で切り替わる。縮んだレイヤーはミップマップの 2 つの段の間を補間する（トライリニア。段 k の座標は 1/2^k、段の外は透明として平均する）。
- **モーションブラー**: `mblur` のレイヤーに。シャッター角（`mblur.angle`、既定 180）と位相（`mblur.phase`、既定 −角/2）の間の時刻を `mblur.samples` 回（既定 16）重ねる。レイヤーの動きとカメラの動きの両方がぶれる。
- **被写界深度**: `camera.aperture`（レンズの口径、画素）が 0 より大きいとき。レンズの上の位置を変えた標本を `camera.samples` 回（既定 16）重ねる（薄いレンズ。ピントの距離 `camera.focus`、既定は注視点までの距離）。
- **ライト（任意）**: `light.type=parallel` か `point`。面の中央での向きで明るさを決める: 明るさ = `light.ambient + (1 − light.ambient) × light.intensity × |n·L|`（両面）。既定（ambient 0.25、intensity 1）では、正面から当たる面は元の明るさ（1 倍）、真横から当たる面は 0.25 倍。ライトを置いただけで正面のレイヤーが明るくなったり白が飛んだりはしない。
- **キーフレーム**: どの値も m6-anim と同じ書き方で時間で変えられる（下の「キーフレーム」）。

## .mzc での書き方

```
project size=1920x1080 camera.z=-3000 camera.ty=500 light.type=point light.y=-400 mblur.angle=180
image "logo.png" z=-200 ry="0@0 360@2" mblur
video "a.mp4" track=1 z=400 rx=10 ry=-30 scale=0.8
text "タイトル" z="0@0 -600@1.5" oy=-200 anchor=0,40
```

- 3D だけのキー（`z` / `ox` / `oy` / `rx` / `ry`）がある行は 3D レイヤーになる（AE の 3D スイッチの代わり）。`z=0` だけでもよい。`mblur`（`mblur=1`、`mblur` とだけ書いてもよい）はモーションブラーのスイッチで、それだけでは 3D にならない（2D のレイヤーでは 2D のモーションブラーになる）。
- `rotation` / `scale` / `anchor` は 2D の変形と同じキー（下の「キーの名前」）。それだけでは 3D にならない。
- キーの一覧・型・既定・範囲は `t3Keys()`（schema にそのまま足せる形、31 項目）。

## キーの名前（M6 のほかの部品とそろえる）

キーの名前の空間は `keys.um` の 1 つなので、同じ考えのキーは同じ名前・同じ型にする。

| キー | 型 | 2D のレイヤー | 3D のレイヤー | そろえる相手 |
| --- | --- | --- | --- | --- |
| `rotation` | angle | 2D の回転（[m6-xform.md](m6-xform.md)） | Z 軸のまわりの回転（`rx`・`ry` の後に掛ける。AE の 3D レイヤーの「Z 回転」） | m6-anim の `rotation`、m6-shape の `rotation` |
| `scale` | string（数か 横,縦） | 2D の拡大 | 3D の拡大 | m6-shape の `scale`（m6-anim の見込んでいる `scale2` は `scale` にそろえてほしい） |
| `anchor` | vec2（x,y） | 2D の基準点 | 3D の基準点 | m6-anim の `anchor`（意味はレイヤーの中央からの画素。既定 0,0） |
| `ox` / `oy` / `z` / `rx` / `ry` | number / angle | — | 3D だけ | — |
| `mblur` | flag | — | レイヤーのモーションブラー（2D でも 3D でも。書いても 3D にはならない） | `mute` と同じ flag |

- 2D のレイヤーに `rotation` を書いた後で `z=0` を足して 3D にすると、同じ `rotation` が Z 回転として効く（AE で 3D スイッチを入れたときと同じ。`rz` というキーはない）。
- project の行のキーは、3D の部品のキーだと分かるように前置きを付ける: `camera.*`（アンチエイリアスは `camera.aa`）、`light.*`（ライトの種類は `light.type`）、`mblur.*`。

## キーフレーム（m6-anim とそろえる）

キーフレームの書き方・評価・書き戻し・`key` の操作・診断は、m6-anim（`src/effects/anim/anim.um`）が正本。3D の部品は同じ書き方を使う:

```
ry="0@0 90@2:hold 0@3"      値@時刻[:印] を空白で並べる（空白を含むので "..." で囲む）
anchor="0,0@0 40,-20@1"     2 次元の値は x,y（コンマは値の中の区切り。キーの区切りは空白）
scale="1@0 1.5,0.8@2"       scale は数か 横,縦（数は縦横同じ）
```

- **いまの実装は仮**: m6-anim がまだ main にないので、`t3anim.um` の `T3Track` がその書き方の一部（秒・分:秒の時刻、`linear` / `hold` / `ease` / `easein` / `easeout` の印、数と x,y の値）を読む。イーズは m6-anim と同じ速度 0 のベジェで補う。smooth・速度（in= / out=）・cubic などの印、`45f` のようなコマ、`end-0.5` は「m6-anim を組み込むまで 3D のキーでは使えません」の診断（m6-anim と同じ code: `anim-bad-interp` / `anim-bad-time`）を返す。
- **差し替える所**: 3D の部品がトラックに触るのは `t3TrackEval`・`t3TrackEvalC`・`t3TrackSet`・`t3TrackMoves`・`t3TrackAnyAbove` の 5 つと、読み取りの `t3ParseTrack` だけ（`t3EvalLayer` / `t3EvalCam` / `t3ShadeOf` / `t3LayerMoves` / `t3SceneDof` はこれらを通す）。m6-anim を組み込んだら、`T3Track` を `AnimTrack` に、`t3ParseTrack` を `animParse` + `animResolve`（クリップの長さと fps で時刻を決める）に、評価を `animEvalNum` / `animEval` に置き換える。`t3TrackMoves` は「キーの値がすべて同じでない」、`t3TrackAnyAbove` は「どれかのキーの値が x より大きい」で、m6-anim の側に同じ関数を足すか、`AnimTrack.keys` から作る。
- **キーの操作**: 3D の部品は `key` / `unkey` の操作を足さない。キーを置く・消す・ずらす・補間を変えるのは m6-anim の `key add / remove / move / set / ease / shift / clear`（`anim_ops.um`）をそのまま使う（時刻の意味もそちらにそろう）。
- **書き戻し**: `t3TrackText` は m6-anim と同じ形で書く。時刻と値は 10^-6 で丸め、`String` の最短の形にする（読み直すと同じ値。1/30 秒と 1/29.97 秒のキーも別のキーのまま読み直せることを試験で確かめている）。
- **数の読み取り**: `t3ParseNum` は仮数を整数で作ってから 10 の累乗で 1 回だけ割るので、15 桁までの数は正しく丸める（`"0.3"` は 0.3、`"1.15"` は 1.15）。組み込むときは text.um の `parseNum` / `parseTime` に替えてよい。

## モデル（model の行。`t3mesh.um`）

.obj のモデルを、3D レイヤーと同じ空間・同じカメラで描きます。

```
project size=1920x1080 light.type=point light.x=300 light.y=-300 light.z=-900
color 304060 w=1200 h=1200 z=0 rx=80 oy=300
model "media/cup.obj" size=500 z=-150 ry="0@0 360@4" color=e0a060 dur=4
```

- **行**: `model "<.obj>"` のあとに、3D レイヤーのキー（`x` / `y` / `ox` / `oy` / `z` / `rx` / `ry` / `rotation` / `scale` / `anchor`）と、`size`（いちばん長い辺の画素。既定は画面の短い辺の半分）、`color`（既定 c8c8c8）、`opacity`、`fade*`、`dur` / `at` / `track` / `id`。3D だけのキーがなくても、いつも 3D で描く。
- **.obj の読み取り**（`t3ObjParse`）: `v`・`vn`・`f` だけを読む（`vt`・`mtl`・`g`・`o`・`s` は読み飛ばす）。面の番号は `a`・`a/b`・`a//c`・`a/b/c` と負の番号。多角形は扇形に三角形に分ける。.obj の y が上・z が手前なので、y と z の符号を変える。外接の箱の中央を原点に、いちばん長い辺を 1 にそろえる。すべての角に `vn` があればなめらかに、なければ面の向きで陰影を付ける。
- **読めないとき**: ファイルがない・数が読めない・番号が範囲の外・面がない・形がない、のどれでも、`render` / `preview` が「N 行目: モデル '…' を描けません（…）」で止まる（`checkMedia`）。`check` はファイルを読まない。
- **描き方**: 頂点を CPU でカメラの空間に移して画面に投影し、三角形を 16 × 16 画素の升に振り分ける。`t3MeshKernel` が画素ごとに升の三角形だけを調べ、画素の中の 4 点でいちばん近い三角形を選び、拡散（Lambert）とつや（Blinn）で陰影を付けて平均する。結果は画素ごとの色（プリマルチプライ）と奥行き（カメラから見た z。平らなレイヤーの `dz / qz` と同じ物差し）。
- **重ね方**: `t3RenderModels` は、モデルの結果を最初の 16 枚の組の画素ごとの並べ替えに 1 枚として差し込む。平らなレイヤーとモデルは画素ごとに前後し、交わる所も正しく切れる。モデルどうしは、三角形の奥行きで前後する（画素の中の 4 点ごと）。
- **光**: `light.type` があれば、その位置（point はモデルの中央から、parallel は画面の中央から見た向き）と `light.ambient` / `light.intensity`。なければ左上手前からの既定の光（環境光 0.3）。面は両面で、見る側に向けて陰影を付ける。
- **まだできないこと**: モーションブラー・被写界深度・`camera.aa` の標本はモデルに効かない（コマの時刻・レンズの中心で 1 度だけ描く）。テクスチャ・材質（mtl）・glTF は読まない。カメラより後ろへ出た頂点のある三角形は描かない。16 枚を超える平らなレイヤーとは、最初の組の中でだけ前後する。描画モード・トラックマット・効果はモデルに掛からない。
- **速さ**: 1920x1080、Ryzen 9 3900X（CPU）で、20 万三角形のドーナツを画面の半分の大きさに描いて、1 コマの preview が約 0.25 秒増えた（.obj 17 MB の読み取りを 2 回含む）。

| code | いつ | 重さ |
| --- | --- | --- |

| `anim-bad-value` | 値が読めない（`anchor=3` のように 2 次元のキーに数を 1 つ） | 誤り |
| `anim-bad-time` | 時刻が読めない（いまはコマ・end からの時刻も） | 誤り |
| `anim-bad-interp` | 補間の印の誤り（いまは linear / hold のほか） | 誤り |
| `anim-key-overlap` | 同じ時刻のキーが 2 つ | 誤り |
| `anim-key-order` | キーが時刻の順でない（並べ替えて使う） | 注意 |
| `bad-number` | 数として読めない（`camera.samples` などの int） | 誤り |
| `out-of-range` | 範囲の外（キーフレームの値もすべて確かめる。`scale` は −100..100、`camera.fov` は 1..170、`light.ambient` は 0..1 など） | 誤り |
| `bad-enum` | `light.type=` / `mblur=` の値の誤り | 誤り |
| `3d-heavy`（新しい） | 描くときの見積もり（1 画素あたり 標本 × 画面を覆うレイヤー）が 256 を超えた（`t3StatsWarning`） | 注意 |

`anim-*` は m6-anim と同じ code（新しく足すのは m6-anim の担当）。`T3Diag` は `Diag` と同じ欄（col は 0）と `warn`。`project.um` で `warn` なら `warnDiag(...)`、でなければ `diag(d.code, d.line, d.col, d.msg, d.hint)` に写す。`3d-heavy` / `3d-atlas` は描くときに分かるので、書き出しの報告（report.um）やプレビューの表示に出す。

## 部品（ファイル）

| ファイル | 中身 | 主な公開 |
| --- | --- | --- |
| `t3math.um` | f64 の三角関数（度、0/90/180 度はちょうど）、回転、面、カメラの基底、射影の行列 | `T3Xf` `T3CamXf` `t3Plane` `t3Homography` `t3DefaultCam` `t3ZoomFromFov` |
| `t3anim.um` | キーフレームの仮の実装（m6-anim の書き方の一部）、時刻をずらす、数の読み取り | `T3Track` `t3ParseTrack` `t3TrackEval` `t3TrackEvalC` `t3TrackText` `t3TrackShift` `t3ShiftText` `t3ParseNum` |
| `t3parse.um` | キーの表、行の kv からの読み取り、診断 | `t3IsLayerKey` `t3IsLayerOnlyKey` `t3LayerKeyKindOf` `t3IsSceneKey` `t3ParseLayer` `t3ParseScene` `t3Keys` `T3LayerSpec` `T3SceneSpec` `T3Diag` |
| `t3mesh.um` | .obj の読み取り、モデルの投影と升への振り分け、三角形を描く kernel | `T3Mesh` `T3Model` `t3ObjParse` `t3MeshDraw` |
| `t3render.um` | kernel、アトラス（RGBA8）、標本の組み立て、分けた dispatch、描画 | `T3Atlas` `t3AtlasNew` `t3AtlasEstimate` `t3AtlasSetMax` `t3AtlasClear` `t3AtlasPut` `t3AtlasWarning` `T3Work` `t3WorkNew` `T3Layer` `T3Scene` `t3Render` `T3Stats` `t3StatsWarning` |
| `threed_test.um` | 試験（`tests/m6-threed/run.mjs` が使う） | — |

- 依存は `src/effects/threed/` の中だけ（`project.um` などを import しない）。組み込む側が `Clip.kv` を渡す。
- kernel は四則演算・比較・`floor`・`sqrt`・整数のビット演算だけを使い、標本ごとの行列（`T3Gpu`）は CPU で求めて Buffer で渡す。CPU と GPU（wgpu）で画素が 1 つも違わないことを試験で確かめている。
- **アトラス**: レイヤーの画素は 1 つの `RacyBuffer<u32>` に RGBA8（ストレートアルファ、赤が下位の 8 ビット）で集める（kernel に Buffer を可変個は渡せないため）。1 texel 4 バイトで、f32 の 1/4。ミップマップの段も続けて置く（約 1.33 倍）。1080p のレイヤー 16 枚で約 177 MB（f32 では 675 MB だった）。素材は 8 ビットなので、映像と画像では失うものはない（効果で 0..1 の外に出た値は切り詰める）。ミップマップの段は整数の計算で作るので、CPU と GPU で同じ。
- **アトラスの上限**: 既定は 64M texel（256 MiB。1 つの storage のバインディング）。`t3AtlasSetMax` で下げられる（GPU の `maxStorageBufferBindingSize / 4` 以下にする）。入りきらないレイヤーは、元の大きさの段を省いて縮めて入れ（`a.reduced`）、一番小さい段も入らなければ描かない（`a.dropped`）。どちらも `t3AtlasWarning` で注意の文を返す。
- **重い場面の分け方**: 1 回の dispatch の「画素 × 標本 × レイヤー」を外接の四角の面積から見積もり、`T3_WORK_MAX`（約 3300 万）を超えるときは、標本を 8 ずつの組に分け、さらに画面を帯に分けて dispatch する。和は `T3Work`（画素ごとに 5 つの f32）に貯め、最後に割る。RTX 5060 Ti で 1 回の dispatch は平均 24 ms（全体を 1 回にすると 637 ms で、遅い GPU では Windows の TDR の 2 秒を超えるおそれがあった）。
- 1 回の kernel で重ねるのは 16 枚まで（画素ごとの並べ替えの配列の大きさ）。超えると中央の奥行きで遠い順に 16 枚ずつ描く（組の間の交わりは扱わない）。

## 組み込み方

1. **`keys.um`**: `coreKeys()` の最後で `t3Keys()` の項目を `KeyInfo` に写して足す（欄は同じ）。型は既存の number / int / flag / enum / string と、m6-anim の足す angle / vec2。どの値にもキーフレームを書けることは m6-anim の担当が schema に書く。

2. **`project.um`**:
   - video / image / text / color の行で `t3IsLayerKey(key)`、project の行で `t3IsSceneKey(key)` のキーは、値の形を確かめずに `kv` に残す（`@` を含む値と同じ扱い）。`rotation` / `scale` / `anchor` は 2D の変形の担当と同じキーなので、表に 1 度だけ載せる。
   - 値のない `mblur` は `mute` と同じに `("mblur", "1")` か `("mblur", "")` で kv に入れる（どちらも 1 と読む）。
   - 行を読み終えたら `t3ParseLayer(c.kv, line, mut d3)` / `t3ParseScene(kv, line, mut d3)` を呼び、`d3` を上の「誤り」のとおりに写す。結果は `Clip.d3: T3LayerSpec` と `Project.scene3d: T3SceneSpec` に持つ（フィールドを足す）。
   - audio の行の 3D のキーは `key-not-allowed`。`camera.` / `light.` / `mblur.` で始まる知らないキーは `unknown-key`（`t3HasScenePrefix`）で、hint に `t3Keys()` から近い名前。古い書き方（`light=`、`aa=`、`rz=`、`ax=` / `ay=`、`sx=` / `sy=`）は `unknown-key` になり、hint に新しい名前を出す。

3. **`render.um`**: 3D のクリップ（`c.d3.is3d`）は、効果があってもなくても必ず「層」を作り、canvas に重ねる代わりにアトラスに入れる。既存の描き方では、効果のない text（`renderTextClipCached`）と color（`fillRect`）は canvas に直接描いて層を作らないので、そこを分ける。例として、次の関数を render.um に足す:

   ```
   // 3D のクリップの層を作ってアトラスに入れ、T3Layer を返す（描くものがなければ null）。
   function clipLayerFor3d(c: Clip, m: Media, p: Project, font: Font, alpha: f32, lt: f64, rc: mut RenderCache, atlas: mut T3Atlas): T3Layer | null
   ```

   - **video / image**: `drawVideo` / `drawImage` の `drawLayer(...)` の手前で分ける。`rc.layer` に `yuvToLayer` / `rgbaToLayer` した後、`c.d3.is3d` なら `drawLayer` を呼ばずに、`fxComposite` と同じ余白の決め方（`clipFxReach(c)`、image と text は透明な余白を足した `big` に `applyClipFx`、映像は `rc.layer` にそのまま `applyClipFx`）で効果を掛けた層を作り、`t3AtlasPut(mut atlas, 層, 層の幅, 層の高さ)` で入れる。`baseX = resolvePos(c.x, m.w, p.width) + m.w / 2`、`baseY = resolvePos(c.y, m.h, p.height) + m.h / 2`（余白は左右・上下に同じだけ足すので、中央は変わらない）。
   - **text**: 効果がなくても `textClipLayer(c, p, font, mut rc.text)` で層 `lo` を作る（`renderTextClipCached` は使わない）。効果は上と同じに掛ける。`baseX = lo.x + lo.w / 2`、`baseY = lo.y + lo.h / 2`（`x` / `y` の `resolvePos` からではない）。
   - **color**: 効果がなくても `w × h` の層（`rcLayer(mut rc, w * h)`）を `clearCanvas(colorVec(c.color))` で塗る（`fillRect` は使わない）。`baseX = resolvePos(c.x, w, p.width) + w / 2`、`baseY` も同じ。
   - 返す `T3Layer { slot, spec: c.d3 の写し, baseX, baseY, start: c.at, alpha }`。`alpha` は 2D と同じ不透明度 × フェード。
   - `renderFrame` の `drawOrder` の繰り返しで、続けて並ぶ 3D のクリップを 1 組として `T3Layer` を集め、次の 2D のクリップの前と繰り返しの後（project の効果 `p.fx` の前）に `t3Render(mut canvas, { spec: p.scene3d, cw: p.width, ch: p.height, fps }, layers, atlas, mut work, t)` で重ねる（AE と同じく、間に 2D のレイヤーがあると 3D の組が分かれる）。
   - `T3Atlas` と `T3Work` は `RenderCache` の外（呼ぶ側が別の変数で持って渡す）に置く。`rc.layer` と `rc.atlas` を同じ呼び出しに渡すと、同じ変数を mut と別の引数で渡すことになり書けないため。最初に `t3AtlasNew(t3AtlasEstimate(p.width, p.height) * 8)` のように見積もりで確保し（最初のコマで倍々に広げて写すと 1080p 16 枚で約 2 秒かかる）、毎コマ `t3AtlasClear` で使い回す。`T3Work` は `t3WorkNew()` で 1 度だけ作る（重い場面で初めて画素の数 × 5 の f32 を確保する）。
   - `t3StatsWarning(st)` と `t3AtlasWarning(atlas)` が "" でなければ、`3d-heavy` / `3d-atlas` の注意にする。

4. **`ops.um`**（split / trim の時刻のずれ）: レイヤーのキーの時刻はクリップの始まりからの秒なので、クリップの始まりが変わる操作では、3D のキー（`t3LayerKeyKindOf(key) > 0` のキー。m6-anim を組み込んだ後は、キーフレームの値すべて）の時刻をずらす。
   - **split の後半**（`<id>_2`。`at` が後ろへ `d = 分けた時刻 − 元の at` だけずれ、kv はそのまま写る）: 3D のキーの値を `t3ShiftText(val, t3LayerKeyKindOf(key), d)` に置き換えて `setKey` する。0 秒より前に出たキーは消え、代わりに元の時刻 `d` の値（補間した値。ホールドならホールドのまま）が `0@0` として先頭に入るので、見た目の動きは変わらない。例: `at=0 dur=4 ry="0@0 360@4"` を 2 秒で split すると、後半は `ry="180@0 360@2"`。
   - **split の前半**: 終わりより後ろのキーはそのまま残す（補間に使う。m6-anim では `anim-key-outside` の注意）。
   - **trim start**（`at` を `d` だけ後ろへ動かし、in も同じだけ動かす）: 後半と同じに `t3ShiftText(..., d)`。前へ広げる（`d` が負）ときは、キーが後ろへずれる。
   - 書き戻した値は空白を含むことがあるので、`.mzc` に書くときは `"..."` で囲む（m6-anim の `animQuoted` と同じ）。
   - fade のように split で分ける処理（ops.um の 732〜776 行あたり）と同じ所に足す。
   - **cut（リップル削除）とカメラのキー**: project の行のカメラ・ライトのキーは全体の時刻なので、cut で後ろのクリップが詰まっても動かない（AE のコンポジションのカメラと同じ）。そのため、カメラの動きと素材の合わせが cut の後ずれる。いまは自動でずらさず、cut の desc に「カメラ・ライトのキーは全体の時刻のままです（必要なら key shift で動かします）」と書き、AI と人が気付けるようにする。キーを動かすのは m6-anim の `key shift`（project の行に対しても使えるようにする）。
   - 3D の部品は `key` / `unkey` の操作を足さない（上の「キーフレーム」）。

5. **診断の code の表**: `3d-heavy`・`3d-atlas`（注意）を足す。`anim-*` は m6-anim の担当が足す。前の版の `bad-keyframe` はやめた。

6. **README**: 上の「.mzc での書き方」と「キーの名前」の表を足す。

## 速さ（1920x1080、1 コマ）

Windows 11、Ryzen 9 3900X（24 スレッド）、RTX 5060 Ti（Vulkan）、wgpu-native v29.0.1.1。1280x720 のレイヤー 4 枚（回転と奥行きあり）。結果を CPU で読む時間（GPU は読み戻し）を含む。ほかの 8 人の作業と同時に測ったので、標本 1 の場合でも前の版の 1.5〜2 倍の値が出ていて、数割〜2 倍ぶれる。

| 場合 | CPU（全コア） | GPU（wgpu） |
| --- | --- | --- |
| 標本 1 | 33〜41 ms | 17〜21 ms |
| `camera.aa=4` | 105〜109 ms | 23〜26 ms |
| モーションブラー 16（分けた dispatch） | 374〜456 ms | 38 ms |
| 被写界深度 16（分けた dispatch） | 331〜385 ms | 61 ms |
| 画面を覆う 16 枚 + `camera.aa=64`（`3d-heavy` の注意。dispatch 65 回） | 11.6 秒 | 1.59 秒（1 回の dispatch は平均 24 ms） |
| 1 コマ全体（素材 4 枚をアトラスへ写し、ミップマップを作り、描いて読む。標本 1） | 38〜44 ms | 32〜38 ms |

GPU の時間の多くは 1920x1080 の読み戻し（約 7 ms）と素材の送り。`dispatch` の自動判断は kernel ごとに測って選ぶので、重い標本は GPU を選ぶが、軽い場合は CPU を選ぶことがある。

## まだないもの

- キーフレームの補間は直線とホールドだけ（ease などは m6-anim を組み込むと使える）。
- 点光源の明るさは面の中央で決める（画素ごとの陰影、影、色つきのライトはない）。
- 3D の文字（押し出し）、レイヤーの向き（orientation）、親子（ペアレント）。
- 被写界深度・モーションブラーの標本は固定の数（適応的に減らさない）。大きくぼかすと標本の重なりが見えるので、`camera.samples` を増やす。
- アトラスは 8 ビット。HDR の素材が入ったら、f16 を 2 つずつ u32 に詰める形にする。
