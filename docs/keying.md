# キーイング（M6: 合成とモーショングラフィックス）

緑や青の背景で撮った素材を抜いて、ほかの映像に重ねるための効果です。どれも効果のプラグイン（`plugins/*.um`）なので、
クリップの行に書くだけで使えます。画素の処理はすべて kernel で、CPU と GPU（`UM_WGPU=1`）で全部の f32 のビットが同じ結果になります。

| 効果 | すること | ファイル |
| --- | --- | --- |
| `chromakey` | キーの色（既定は緑の布の色）に近い所を透明にし、縁の色から背景の色を差し引き、被写体に映り込んだキーの色（こぼれ）を取る | `plugins/chromakey.um` |
| `lumakey` | 暗い所（`invert=1` で明るい所）を透明にする | `plugins/lumakey.um` |
| `matteview` | アルファを白黒で見せる（`=2` で市松模様の上に重ねる）。抜け具合を確かめる用 | `plugins/matteview.um` |

## 書き方

**キーの効果はクリップの行に書きます。** `project` の行（画面全体）に書いても意味がありません。画面全体は書き出すときにアルファを
見ないので、抜けた所は黒っぽい色のまま出ます。

```
# 緑の背景の人物を、背景の画像の上に重ねる（上のトラックに置く）
image "studio.png" track=0 dur=10
video "talent.mp4" id=talent track=1 at=0 chromakey=0.3 chromakey.shrink=1 chromakey.feather=1

# 青い背景（キーの色は下の表から）
video "blue.mp4" chromakey=0.3 chromakey.r=0.1 chromakey.g=0.2 chromakey.b=0.9

# 抜け具合を見る（書き出しの前に消す）
video "talent.mp4" chromakey=0.3 matteview=1
video "talent.mp4" chromakey=0.3 matteview=2

# 黒い背景のロゴを抜く / 白い紙を抜く
video "logo_on_black.mp4" lumakey=0.08 lumakey.softness=0.1
image "scan.png" lumakey=0.85 lumakey.invert=1 lumakey.softness=0.1
```

`chromakey` だけ（値なし）でも既定の値で効きますが、**`chromakey=<値>` の形で書くことを勧めます**（下の「外し方」）。

操作も同じ書き方です（`node tools/mozcut.mjs op p.mzc set talent chromakey.tolerance=0.45`）。範囲の外は `out-of-range` の診断になります。

### 外し方

効果は、その効果のキー（`chromakey` と `chromakey.<引数>`）が 1 つでも行に残っていれば効きます。外すときは**書いたキーをすべて消します**。

```
node tools/mozcut.mjs op p.mzc unset talent chromakey chromakey.shrink chromakey.feather
```

- `unset talent chromakey` だけでは `chromakey=…` しか消えず、`chromakey.shrink` などが残って効果が効いたままになります。
- 値なしの `chromakey`（旗の形）は、いまの `unset` では消せません（`mute` 以外の旗を扱わないため）。`chromakey=0.3` の形で書いておけば消せます。
- 行にどのキーがあるかは `node tools/mozcut.mjs show p.mzc` で見られます。

（コアへの提案: `unset <id> <効果>` で、旗の形と `<効果>.*` の子のキーをまとめて消すようにする。報告を参照）

### よく使うキーの色

| 背景 | `chromakey.r` | `chromakey.g` | `chromakey.b` | 16 進の目安 |
| --- | --- | --- | --- | --- |
| クロマグリーン（既定） | 0.1 | 0.7 | 0.3 | `#1ab34d` |
| デジタルグリーン（明るい） | 0.25 | 0.85 | 0.25 | `#40d940` |
| クロマブルー | 0.1 | 0.2 | 0.9 | `#1a33e6` |
| 暗い照明の緑 | 0.05 | 0.45 | 0.2 | `#0d7333` |

いちばん合うのは、素材の背景の色を測った値です（編集画面のスポイトは、効果を掛ける前の素材の画素を 5x5 で平均し、
`set <id> chromakey.r=.. chromakey.g=.. chromakey.b=..` を 1 つの操作で送る予定）。16 進の値（`#00b140`）で書く形は、
プラグインの宣言に色の型ができてから入れます（生成器の担当への提案）。いまは 16 進の各 2 桁を 255 で割った値を書きます
（`#00b140` → `r=0 g=0.694 b=0.251`）。

### chromakey の引数

| 引数 | 既定 | 範囲 | 意味 |
| --- | --- | --- | --- |
| `tolerance`（主） | 0.3 | 0..1 | 許容。キーの色からの色の差 d がこれ以下なら透明。d はキーの色の鮮やかさを 1 とする（灰色・白・黒は 1） |
| `softness` | 0.5 | 0..1 | 許容からこの幅で、透明から不透明へ直線で変わる（キー = (d - 許容) / 柔らかさ）。0 なら 0 か 1 で、縁の推定もしない |
| `spill` | 1 | 0..2 | 色のこぼれの除去。0 で取らない、1 でキーの色の成分をほかの 2 つの大きいほうまで、2 で 2 つの平均まで下げる |
| `shrink` | 0 | -16..16 | エッジの収縮（画素。正で縮め、負で広げる） |
| `feather` | 0 | 0..32 | エッジのぼかし。箱ぼかしを 2 回掛けるので、広がりはおよそ 2×feather 画素 |
| `r` `g` `b` | 0.1 0.7 0.3 | 0..1 | キーの色 |

#### 抜き方

- 色の差 d は BT.709 の Cb / Cr の平面で測ります。キーの色と灰色（白・黒）を 1-t : t で混ぜた色の d は t、
  同じ色相で明るさが L 倍の背景の d は 1 - L です。
- **暗い背景と影。** 色だけでは「暗い背景」と「背景と黒い被写体が混ざった縁」を区別できません。既定では、明るさが 7 割ほどまでの
  背景は透明になり、それより暗い所（濃い影、周辺の光の落ち）は**半透明の黒**になります（影として重ねる先を暗くする）。
  - 例: 明るさ 0.5 の影は、アルファ 0.4 の黒。明るさ 0.4 は 0.6 の黒。
  - 暗い所も透明にしたいときは、許容を上げます（`chromakey=0.55` なら明るさ半分の背景まで透明）。
    そのぶん黒い被写体の縁も薄くなります。照明のむらが大きい素材は、ガーベッジマットで背景の隅を消すのが確実です。
- **縁の色を戻す。** 縁の半透明の画素は「背景の色と被写体の色の混ざり」なので、背景の色を差し引いて被写体の色に戻します。
  1. 全体の推定: キーの色の量を引く（キーと灰色の混ざりは、ちょうど元の灰色に戻る）。
  2. 周りの推定（softness > 0 のとき）: 周り（8 方向に 1, 2, 3, 5, 8 画素の 40 か所）に、はっきりした背景とはっきりした被写体の
     画素があれば、2 つの色を結ぶ線に画素を射影して混ざり具合 t を求め、そこから色とアルファを決めます。
     赤や肌のように鮮やかな被写体の縁も、灰色やオリーブ色の線にならず、被写体の色の半透明になります。
  - 例（キーの色と被写体を 1-t : t で混ぜた 1 画素の縁。試験あり）:

    | 被写体 | t = 0.25 | t = 0.5 | t = 0.75 |
    | --- | --- | --- | --- |
    | 白 | 透明 | アルファ 0.4、色は白 | アルファ 0.78、色は白 |
    | 肌 (0.9, 0.7, 0.55) | ほぼ透明 | アルファ 0.5、色は肌 | アルファ 0.78、色は肌 |
    | 赤 (0.8, 0.1, 0.1) | アルファ 0.22、色は赤 | アルファ 0.5、色は赤 | アルファ 0.78、色は赤 |

  - 限界: 周り 8 画素の中にはっきりした被写体の画素がない細い半透明の物（髪の毛の先など）は、全体の推定だけになり、
    不透明寄りで少し色が残ります。`softness` を広げる（例: `chromakey=0.2 chromakey.softness=0.7`）と薄くなります。
- **こぼれの除去**（縁の色を戻した後に掛ける）: `spill=1` は黄色・水色を変えません。キーの色が (0.1, 0.7, 0.3) のように B > R だと、
  緑を取った所が青緑（G = B）に寄るので、気になるときは `spill=2`（G を R と B の平均まで）にします（黄色・水色も少し変わります）。
  下げた分の明るさは灰色で足し戻します。
- 結果のアルファは「元のアルファ × キー」です（元より大きくならない）。収縮とぼかしはキーにだけ掛かります。
- キーの色が灰色に近い（鮮やかさ 0.01 未満）ときは何もしません（抜かない・こぼれも取らない）。明るさで抜くなら `lumakey` です
  （診断 `chromakey-gray-key` の提案は報告を参照）。
- 縁に背景の色の線が残るときは `shrink=1`、硬いときは `feather=1`〜`2`。

### lumakey の引数

| 引数 | 既定 | 範囲 | 意味 |
| --- | --- | --- | --- |
| `threshold`（主） | 0.1 | 0..1 | しきい値。明るさ（BT.709 の Y）がこれより暗い所を透明にする（`invert=1` なら明るい所） |
| `softness` | 0.1 | 0..1 | しきい値から**明るい側へ**この幅で、透明から不透明へなめらかに変わる（`invert=1` なら暗い側へ）。0 なら境目がくっきり |
| `invert` | 0 | 0..1 | **0 か 1** を書く。1 で明るい所を抜く（0.5 以上は 1 とみなす） |
| `shrink` / `feather` | 0 | | chromakey と同じ |

- `threshold=0` は何も抜きません（純粋な黒も残る）。`invert=1` で `threshold=1` も何も抜きません。
- `softness=0` では「しきい値より暗い（y < しきい値）」所だけが透明です（しきい値ちょうどは残る）。
- After Effects のルミナンスキーと違い、柔らかさはしきい値を中心に両側へは広がらず、片側（明るい側）だけです。
  「明るさ 0.1 から 0.3 までをなめらかに」なら `lumakey=0.1 lumakey.softness=0.2` です。
- 炎や光のように黒い背景の上に明るく重ねたい素材は、キーで抜くより合成のモードのスクリーン / 加算のほうが自然です。

## ガーベッジマット（マスク）との組み合わせ

マスクは別の部品が受け持ちます。キーイングの側の約束は次の 2 つです。

1. **アルファは掛け合わせ。** キーは「元のアルファ × キー」にするので、マスクもアルファに掛ける形（`a = a × マスク`）にすれば、
   行に書く順によらず「キーで抜けた所 かつ マスクの中」になります（収縮・ぼかしがなければ、前後で全部のビットが同じ。試験あり）。
2. **収縮・ぼかしを使うときは、マスクを後ろに書く。** キーは元のアルファが 0 の画素を「キー = 1（影響しない）」として収縮・ぼかしに渡すので、
   マスクを前に書くと、マスクの縁にキーのぼかしが掛かります。

```
video "talent.mp4" chromakey=0.3 chromakey.feather=1 <マスクの効果>...      ← ガーベッジマット（照明やスタンドを消す）は後ろ
```

被写体の中の緑（緑の服など）を残す「ホールドアウト」は、キーの後ろで `a = max(a, マスク)` にするマスクのモードがあればできます（マスクの担当への頼み）。

## 生成器と wasm 版について

3 つのファイルには、いまは帯に分けない宣言（`@whole`）を付けていません（master の `tools/gen-plugins.mjs` が知らない宣言で、
付けるとエンジンのビルドが止まるため）。組み込み版の結果には関わりません。wasm 版（`.mzplug`）で帯に分けて実行する仕組みが
master に入るとき、同じコミットか後のコミットで `// @whole` を足します（収縮・ぼかし・縁の推定・市松模様が帯の境目でずれないように）。

## 試験

```
node tests/m6-key/run.mjs                  宣言の試験（master の生成器で読めること。読めなければ落ちる）、既知の値の試験、
                                           ffmpeg で作った緑の背景の素材での試験
node tests/m6-key/run.mjs --gpu --bench    あわせて CPU と GPU の比べ合わせ（全部のビット）と、1080p の 1 コマの速さ
node tests/m6-key/run.mjs --shots <dir>    結果の画像（PNG）
```

素材は ffmpeg で作ります: 照明のむら・ノイズ・影のある緑の背景の前に、肌・髪（70% の不透明さの毛）・しま模様の服の人形
（縁は柔らかく、服と肌には緑のこぼれを足してある）。

### 速さ（1920x1080、1 コマ。CPU は 24 スレッド、GPU は RTX 5060 Ti / Vulkan。5 回の最小）

| | CPU | GPU（送りと読み戻しを含む） | GPU（層を置いたまま） |
| --- | --- | --- | --- |
| chromakey 既定 | 19 ms | 18 ms | 1.5 ms |
| chromakey shrink=1 feather=2 | 37 ms | 33 ms | 12 ms |
| chromakey shrink=4 feather=8 | 51 ms | 30 ms | 15 ms |
| chromakey shrink=16 feather=32（範囲の上限） | 58 ms | 53 ms | 31 ms |
| chromakey shrink=-16 feather=32 | 57 ms | 48 ms | 32 ms |
| lumakey 既定 | 1.5 ms | 18 ms | 0.4 ms |
| lumakey shrink=1 feather=2 | 19 ms | 28 ms | 11 ms |
| lumakey shrink=16 feather=32 | 38 ms | 42 ms | 29 ms |
| matteview | 1.6 ms | 18 ms | 0.4 ms |

- 収縮・ぼかしは、半径 8 までは画素ごとに窓を読み、それより大きいと行（列）ごとに窓を滑らせます（箱ぼかしは足して引く、
  最小・最大は van Herk の方法）。手間が半径によらないので、範囲の上限でも以前（117 ms）の半分ほどです。
- chromakey の既定は、縁の推定（周り 40 か所を読む）と、作業用の `tmp` を通す分だけ、以前（4 ms）より重くなりました。
- GPU で収縮・ぼかしを使うと、作業用の `Buffer<f32>` / `RacyBuffer<f32>` を毎回新しく作って送る手間（約 8 ms）が入ります。
  UM が「作ったばかりの 0 の Buffer は送らない」ようになるか、描画の側が f32 の作業用を渡せるようになれば減ります。
